# Working in this repository as an agent

This is the public website of the OBT Consultant Development Track. It is built by Claude Code sessions under a written process that lives outside this repository, in the owner's Obsidian vault. This file is the short version an agent working from the clone can read first. Where the two disagree, the vault wins.

## The contract rule

Every workflow built here (anything a person does end to end: sign in, reset a password, submit a form, import a file, resolve a queue item, deploy) is bound to a **delivery contract** before it is built and is not done until the contract is proven. The five parts:

1. **Deliverable**: one sentence naming what a user can observably do.
2. **Constraints**: what the build must not do, each with the script, build step, database constraint or hook that enforces it. A constraint enforced by prose does not count.
3. **Proof**: evidence from the running environment (harness output with counts, a screenshot, a `curl` of the served bundle, the deployed function's body), saved with the command that produced it.
4. **Verification**: a separate agent re-runs the proof commands and reports its own counts; the owner runs a human checklist for what only a person can see. Reading a build record is not verification.
5. **Owner**: agent or human, decided by which environment the proof needs.

An agent's statement that something works is a claim. This repository's own history has a reset flow that sent an email and had no handler for the link, and a green build for every commit in between.

## What gates a deploy

A push to `main` deploys to GitHub Pages. `npm run build` runs `tsc -b`, `scripts/check-labels.mjs`, `scripts/build_eval_nodes.py --check`, the two Vite builds, `scripts/prerender.mjs`, `scripts/csp-hashes.mjs` and `scripts/member-content-gate.mjs`. There is no test runner in CI. The per-spec harnesses in `scripts/` (`site0X-*.mjs`, `*-rls-tests.sql`) run against a live fixture database and are run by the build session and re-run by its reviewer, not by CI.

`.githooks/pre-push` runs the participant-name scan and refuses a push with no fresh proof recorded. Install it once with `npm run hooks:install`. Do not push with `--no-verify`.

A green Actions run proves the build, not the served content. After a push, read the served bundle and grep for a string only the new build carries.

## What never enters this repository

- A participant's name or address, in code, comments, fixtures, screenshots or commit messages. Facilitator names are the one documented exception. `scripts/site08-name-scan.mjs` discovers the forbidden terms from a roster file kept outside the repo and refuses to run when that file is absent.
- Any secret. The only keys here are the publishable class a visitor's browser already holds. `docs/SECURITY.md` is the authority.
- A third-party origin in `index.html`. Fonts are self-hosted; the CSP is generated by `scripts/csp-hashes.mjs`.

## Where the rest is

Specs, build records, review records and the workflow register live in the owner's vault, not here. `docs/SECURITY.md`, `docs/PORTAL.md` and `docs/ASSESSMENT.md` are the parts of the reasoning that are public, and they date and command every claim they make; match that standard when you add to them.
